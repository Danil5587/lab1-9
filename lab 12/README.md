# Лабораторная работа №12 — вариант 5

**Тема:** Реактивное и асинхронное программирование. Потоки данных  
**Задание:** Асинхронная обработка заявок в деканат.

## Описание

Программа принимает заявки в деканат и обрабатывает их асинхронно. Для распределения заявок используется `asyncio.PriorityQueue`: срочные заявки имеют приоритет над обычными, а обычные — над низкоприоритетными.

В проекте реализованы:
- один производитель и два асинхронных потребителя;
- ограниченная очередь `PriorityQueue(maxsize=3)`;
- приоритеты заявок: `срочная`, `обычная`, `низкая`;
- уникальные сигналы завершения `SENTINEL` через отдельный приоритетный элемент;
- проверка номера, категории, описания и приоритета;
- тайм-аут обработки через `asyncio.timeout`;
- корректное завершение через `task_done()`, `queue.join()` и `asyncio.gather()`;
- итоговая статистика по категориям и список ошибок;
- 9 тестовых сценариев.

## Приоритеты

| Тип заявки | Числовой приоритет | Очередность |
|---|---:|---|
| Срочная | 0 | Первая |
| Обычная | 1 | Вторая |
| Низкая | 2 | Третья |

Меньшее числовое значение означает более высокий приоритет. При одинаковом приоритете используется порядковый номер добавления, поэтому заявки сохраняют порядок поступления в очередь.

## Примечание

При нескольких потребителях очередь гарантирует порядок **извлечения** заявок по приоритету, но время завершения обработки может отличаться из-за параллельной работы операторов.
